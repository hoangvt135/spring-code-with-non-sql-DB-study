# 10 — Trang 404: báo "không tìm thấy" cho người dùng

Hiện tại gõ sai địa chỉ hay mở một category không tồn tại, người dùng sẽ thấy trang **Whitelabel Error Page** trắng toát, toàn chữ tiếng Anh. Tệ hơn, hai trường hợp còn cho ra **hai mã lỗi khác nhau**:

| Bạn mở | Đang thấy | Mong muốn |
|--------|-----------|-----------|
| `/orders` (module chưa làm) | Whitelabel, **404** | Trang 404 của mình, có nav |
| `/categories/999/edit` (id không có) | Whitelabel, **500** | Trang 404 của mình, ghi rõ "không tìm thấy category id 999" |
| `/products/999/edit` | Whitelabel, **500** | Như trên |

Mục tiêu bài này: làm **một** trang 404 dùng chung, có layout như mọi trang khác, và cho cả hai trường hợp đều dẫn về đó.

> Bài này chỉ thêm **1 template, 1 class, 1 dòng cấu hình** và sửa **2 dòng** trong Service. Không cần viết controller nào cho trang lỗi cả.

---

## Ý tưởng

### Vì sao `/orders` ra 404 còn `/categories/999/edit` ra 500?

- `/orders`: **không có route nào** khớp. Spring biết ngay đây là "không tìm thấy" → **404**.
- `/categories/999/edit`: route **có**, `editForm()` chạy bình thường, gọi `categoryService.findById(999)`. Service ném `RuntimeException`. Spring chỉ thấy "có exception bay ra mà không ai bắt", không biết nó nghĩa là "không tìm thấy" → coi là lỗi server → **500**.

Vậy ta cần làm 2 việc:

1. **Vẽ trang 404 đẹp**: dùng cho mọi request bị 404.
2. **Cho Spring biết** exception "không tìm thấy" phải trả về 404 chứ không phải 500.

### Spring Boot tìm trang lỗi thế nào

Khi một request bị lỗi, Spring Boot chuyển nó sang đường dẫn nội bộ `/error` (do class có sẵn `BasicErrorController` xử lý). Class này đi tìm template theo thứ tự:

```
Lỗi 404  →  templates/error/404.html   (đúng mã lỗi)
         →  templates/error/4xx.html   (cả nhóm 4xx)
         →  templates/error.html       (mọi lỗi)
         →  Whitelabel Error Page      (không có file nào ở trên)
```

Tức là **chỉ cần đặt file đúng tên, đúng chỗ**, không cần controller. Spring còn tự đưa sẵn các biến sau vào template:

| Biến | Ví dụ giá trị |
|------|---------------|
| `${status}` | `404` |
| `${error}` | `Not Found` |
| `${message}` | `không tìm thấy category id 999` |
| `${path}` | `/categories/999/edit` |
| `${timestamp}` | thời điểm xảy ra lỗi |

### Sơ đồ sau khi làm xong

```
/orders               → không có route ─────────────────────────┐
                                                                ├─► 404 ─► /error ─► templates/error/404.html
/categories/999/edit  → editForm() → findById(999)              │
                         → throw NotFoundException ─────────────┘
                           (@ResponseStatus(NOT_FOUND))
```

Các file sẽ đụng tới:

```
src/main/java/com/example/demo/
├── common/
│   └── NotFoundException.java     ⬅️ MỚI   — exception "không tìm thấy", gắn sẵn mã 404
├── category/CategoryService.java  ✏️ SỬA   — findById() ném NotFoundException
└── product/ProductService.java    ✏️ SỬA   — findById() ném NotFoundException

src/main/resources/
├── application.yml                ✏️ SỬA   — cho phép hiện message lỗi
└── templates/error/
    └── 404.html                   ⬅️ MỚI   — trang 404
```

## Bước 1 — Tạo trang `templates/error/404.html`

Tạo thư mục `src/main/resources/templates/error/` rồi tạo `404.html`:

```html
<!DOCTYPE html>
<html xmlns:th="http://www.thymeleaf.org"
      xmlns:layout="http://www.ultraq.net.nz/thymeleaf/layout"
      layout:decorate="~{fragments/layout}">
<head>
    <title>Không tìm thấy</title>
</head>
<body>
    <section layout:fragment="content">
        <h1>404 — Không tìm thấy</h1>

        <!-- ${path}: địa chỉ người dùng vừa mở -->
        <p>Không có gì ở địa chỉ <code th:text="${path}">/abc</code>.</p>

        <!-- ${message}: nội dung exception, ví dụ "không tìm thấy category id 999" -->
        <p th:if="${message}">Chi tiết: <span th:text="${message}">...</span></p>

        <p>
            <a class="btn" th:href="@{/products}">Về trang sản phẩm</a>
            <a th:href="@{/categories}">Danh mục</a>
        </p>
    </section>
</body>
</html>
```

- Tên thư mục **bắt buộc** là `error`, tên file **bắt buộc** là mã lỗi (`404.html`). Đặt sai tên thì Spring không tìm thấy và vẫn hiện Whitelabel.
- Trang lỗi cũng là template bình thường nên dùng được `layout:decorate` (bài 07): tự có nav, CSS, footer.
- `th:if="${message}"`: chỉ hiện dòng "Chi tiết" khi có message, tránh dòng trống.

Lưu file, mở http://localhost:8093/orders → thấy trang 404 mới, có nav. **Trường hợp module chưa làm đã xong.**

Nhưng `/categories/999/edit` vẫn là 500 → sang bước 2.

## Bước 2 — Tạo `NotFoundException` gắn sẵn mã 404

Tạo `src/main/java/com/example/demo/common/NotFoundException.java`:

```java
package com.example.demo.common;

import org.springframework.http.HttpStatus;
import org.springframework.web.bind.annotation.ResponseStatus;

// Exception riêng cho trường hợp "không tìm thấy".
// @ResponseStatus: khi exception này bay ra khỏi controller mà không ai bắt,
// Spring trả về mã 404 thay vì 500 mặc định.
@ResponseStatus(HttpStatus.NOT_FOUND)
public class NotFoundException extends RuntimeException {

    public NotFoundException(String message) {
        super(message);   // message này sẽ hiện ở ${message} trên trang 404
    }
}
```

Giải thích:
- `extends RuntimeException`: vẫn là `RuntimeException` như Service đang ném, chỉ là **có tên riêng**. Không phải khai báo `throws` ở đâu cả.
- `@ResponseStatus(HttpStatus.NOT_FOUND)`: đây là chỗ "cho Spring biết" exception này nghĩa là 404.
- Vì sao để trong package `common/` chứ không phải `category/`? Vì cả `ProductService` lẫn `CategoryService` (và các model sau này) đều dùng nó. Package theo feature dành cho code của **một** feature; thứ dùng chung thì để riêng.

## Bước 3 — Service ném `NotFoundException`

Chỉ sửa đúng dòng `orElseThrow` trong `findById()`.

`CategoryService.java`:

```java
import com.example.demo.common.NotFoundException;   // ⬅️ thêm import

public Category findById(Long id) {
    return categoryRepository.findById(id)
            .orElseThrow(() -> new NotFoundException("Không tìm thấy danh mục id=" + id));
}
```

`ProductService.java`:

```java
import com.example.demo.common.NotFoundException;   // ⬅️ thêm import

public Product findById(Long id) {
    return productRepository.findById(id)
            .orElseThrow(() -> new NotFoundException("Không tìm thấy sản phẩm id=" + id));
}
```

Chỉ cần sửa `findById()` là đủ: `update()` và `updateCategory()` đều gọi `findById()` trước, nên sửa một id không tồn tại cũng tự ra 404.

## Bước 4 — Cho phép hiện message lỗi

Mặc định Spring Boot **giấu** `${message}` (để tránh lộ thông tin nội bộ ra ngoài), nên dòng "Chi tiết" sẽ trống. Thêm vào `application.yml`, trong khối `server:` đã có:

```yaml
server:
  port: 8080
  error:
    # Cho phép đưa message của exception ra trang lỗi / JSON lỗi.
    # Message của mình viết tiếng Việt, không có thông tin nhạy cảm nên bật được.
    include-message: always
```

> Ở **chế độ dev**, DevTools đã tự bật sẵn cái này, nên bỏ qua bước 4 vẫn thấy message. Nhưng chạy **chế độ thường** (`docker compose up --build`, không có DevTools) thì message sẽ mất. Vì vậy cứ ghi rõ trong `application.yml` để hai chế độ giống nhau.

## Bước 5 — Chạy & kiểm tra

```bash
# Chế độ dev: app tự restart khi có file .java mới / sửa application.yml (xem bài 04)
docker compose -f docker-compose.dev.yml logs -f app-dev

# Chế độ thường: phải build lại image
docker compose up --build
```

Mở trình duyệt, thử lần lượt:

1. http://localhost:8093/orders → trang 404, ghi "Không có gì ở địa chỉ /orders".
2. http://localhost:8093/categories/999/edit → trang 404, "Chi tiết: Không tìm thấy danh mục id=999".
3. http://localhost:8093/products/999/edit → trang 404, "Chi tiết: Không tìm thấy sản phẩm id=999".
4. Bấm **Danh mục**, **Sản phẩm** trên nav → vẫn chạy bình thường.

Kiểm tra mã lỗi bằng lệnh:

```bash
curl -s -o /dev/null -w '%{http_code}\n' http://localhost:8093/orders                 # 404
curl -s -o /dev/null -w '%{http_code}\n' http://localhost:8093/categories/999/edit    # 404 (trước đây là 500)
curl -s -o /dev/null -w '%{http_code}\n' http://localhost:8093/categories             # 200
```

### Bonus: REST API cũng được lợi

`CategoryController` (REST) cũng gọi `categoryService.findById()`, nên API giờ trả **404** thay vì 500:

```bash
curl -s http://localhost:8093/api/categories/999
# {"timestamp":"...","status":404,"error":"Not Found","message":"Không tìm thấy danh mục id=999","path":"/api/categories/999"}
```

Cùng một lỗi, nhưng trình duyệt nhận **trang HTML** còn `curl`/Postman nhận **JSON**. `BasicErrorController` tự chọn dựa vào header `Accept` của request: trình duyệt gửi `Accept: text/html` nên được trang `404.html`, còn `curl` không đòi HTML nên được JSON.

## Vì sao không dùng `@ControllerAdvice`?

Bạn sẽ gặp cách khác trên mạng: viết một class `@ControllerAdvice` + `@ExceptionHandler` để bắt mọi exception ở một chỗ. Cách đó mạnh hơn (tự chọn template, thêm dữ liệu vào model, xử lý nhiều loại lỗi), nhưng là bước nâng cao. Với nhu cầu "không tìm thấy → 404" thì `@ResponseStatus` + `templates/error/404.html` là đủ, và **không cần viết thêm controller nào**.

## Lỗi thường gặp

| Triệu chứng | Nguyên nhân | Cách sửa |
|-------------|-------------|----------|
| Vẫn hiện **Whitelabel** khi mở `/orders` | Sai chỗ/sai tên file | File phải là `templates/error/404.html` (thư mục `error`, không phải `errors`) |
| `/categories/999/edit` vẫn **500** | Service còn ném `RuntimeException` | Đổi thành `new NotFoundException(...)` trong `findById()` |
| Vẫn 500, log ghi `cannot find symbol NotFoundException` | Thiếu `import` | Thêm `import com.example.demo.common.NotFoundException;` |
| Đã ném `NotFoundException` mà vẫn 500 | Quên `@ResponseStatus(HttpStatus.NOT_FOUND)` trên class | Thêm annotation ở Bước 2 |
| Trang 404 hiện nhưng dòng "Chi tiết" **trống** | Thiếu `include-message`, đang chạy chế độ thường | Làm Bước 4 |
| Trang 404 **không có** nav/CSS | Thiếu `layout:decorate` hoặc `xmlns:layout` | Xem lại 3 dòng đầu thẻ `<html>` (giống bài 07) |
| `/categories/abc/edit` ra Whitelabel **400**, không phải 404 | `abc` không đổi được sang `Long` → Spring coi là **400 Bad Request** | Đúng như thiết kế; muốn có trang đẹp thì xem bài tập 1 |

## Bài tập

1. **Trang cho cả nhóm 4xx**: đổi tên (hoặc chép) thành `templates/error/4xx.html`, hiện `${status}` và `${error}` thay vì ghi cứng "404". Thử `/categories/abc/edit` (400) xem có ra trang của bạn không. Nếu vẫn giữ `404.html` thì 404 dùng file đó, các lỗi 4xx khác dùng `4xx.html`.
2. **Trang 500**: tạo `templates/error/500.html` báo "Có lỗi xảy ra, thử lại sau". Thử bằng cách tạm thời `throw new RuntimeException("test")` trong `list()` của một controller. **Đừng** hiện `${message}` ở trang 500 (lỗi server có thể lộ thông tin nội bộ).
3. **Xoá id không tồn tại**: mở `/categories/999/delete` → không báo lỗi gì, chỉ quay về danh sách. Vì sao? (Gợi ý: `deleteById()` của Spring Data bỏ qua lặng lẽ khi không có id.) Sửa `delete()` trong Service để gọi `findById(id)` trước, cho nó ra 404.
4. **Nút "Quay lại"**: thêm vào trang 404 một link `<a href="javascript:history.back()">Quay lại</a>`.
